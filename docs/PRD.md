# AI 出海营销助手（Outbound Studio）产品需求文档 PRD

**版本：** V1.0  
**产品定位：** 面向出海营销服务商的 AI 获客与营销交付助手  
**项目性质：** 可交互业务 Demo  
**开发目标：** 在有限开发时间内，完成五个业务环节的完整演示闭环。

---

## 1. 产品背景

出海营销服务商在日常工作中通常需要完成：

1. 寻找有出海营销需求的潜在企业。
2. 判断企业是否值得优先跟进。
3. 制定个性化客户联系内容。
4. 根据客户需求制定营销服务方案。
5. 将方案转化为执行任务并完成交付。
6. 根据营销数据复盘效果，优化下一轮营销策略。

目前这些环节通常分散在不同工具中，信息容易割裂，重复工作较多。

本产品希望利用 AI Agent 将上述工作串联起来，形成从潜客发现到营销交付的业务闭环。

## 2. 产品目标

开发一个可交互的 AI 出海营销助手 Demo，展示 AI 在营销业务中的实际应用价值。

必须实现以下五个业务模块：

- 潜在客户分析
- 潜在客户联系
- 营销方案撰写
- 执行交付
- 数据复盘

核心要求：

- 五个模块必须围绕同一个模拟客户案例。
- 每个模块都有明确的输入、处理过程和输出结果。
- 展示 Agent 执行过程（Run Trace）。
- 展示数据来源和人工审核机制。
- 前一个模块的输出可以传递到下一个模块。
- 能够从头到尾完整演示一次业务流程。

### 3.1 客户信息

企业名称：星瀚科技（虚构）

企业地区：中国深圳。

所属行业：消费电子。

主营产品：无线蓝牙耳机。

目标市场：美国。

客户现状：

- 有成熟的国内产品和销售经验。
- 正在探索美国市场。
- 海外品牌知名度较低。
- 缺乏海外社媒运营经验。
- 尚未建立成熟的广告投放策略。

潜在营销需求：

- 美国市场竞品分析。
- 海外社媒内容策划。

- 营销数据分析与优化。

所有客户信息和模拟业务数据必须明确标注为演示数据，不得伪装成真实企业信息。

## 4. 功能需求

### 模块一：潜在客户分析（Lead Discovery）

**目标：** 帮助营销服务商发现并判断优先跟进的潜在客户。

输入：

- 目标市场
- 目标国家或地区
- 产品类型
- 客户类型
- 期望潜客数量

功能：

1. 展示潜在客户列表。
2. 展示企业基本信息。
3. 展示客户需求信号。
4. 根据以下维度进行线索评分：
   - 行业匹配度
   - 出海意向
   - 营销能力缺口
   - 可触达性
5. 生成综合评分和优先级。
6. 展示 AI 推荐理由。
7. 提供来源 URL 和核验状态。

Source Check：

- 支持输入多个公开网址。
- 展示待核验、核验成功、核验失败等状态。
- 记录 URL、核验时间和核验结果。
- 如果没有真实网页访问能力，必须明确显示模拟核验或待人工核实。

输出：

- 企业线索列表
- 企业信息
- 线索评分
- 优先跟进建议
- 来源证据

### 模块二：潜在客户联系（Lead Outreach）

**目标：** 根据客户画像生成个性化联系内容。

输入：

- 已筛选客户信息
- 客户需求摘要
- 联系渠道

功能：

1. 生成客户开发邮件。
2. 自动生成邮件主题。
3. 根据企业特点生成个性化正文。
4. 生成后续跟进计划。
5. 支持编辑邮件内容。
6. 支持复制邮件草稿。
7. 展示人工审核状态。

跟进计划示例：

- Day 0：发送首轮邮件。
- Day 3：补充行业观察。
- Day 7：发送相关市场洞察。
- Day 14：无回复则转入长期培育。

输出：

- 邮件主题
- 邮件正文
- 跟进时间线
- 审核状态

禁止未经用户授权真实发送邮件。

### 模块三：营销方案撰写（Proposal Generation）

**目标：** 根据客户需求生成简短、可执行的营销服务方案。

输入：

- 客户基本信息
- 客户需求
- 目标市场
- 营销目标

功能：

1. 生成客户需求摘要。
2. 生成营销目标。
3. 生成营销策略。
4. 生成服务范围。
5. 生成项目周期。
6. 生成交付物清单。
7. 生成验收标准。
8. 支持方案预览和复制。

模拟方案：

项目名称：星瀚科技美国市场首轮营销验证。

周期：4 周。

服务内容：

- 市场研究：分析 5 个竞品账号。
- 内容策划：输出 3 个主题和 6 条视频脚本。
- 内容测试：制定 3 条素材测试方案。
- 数据复盘：分析曝光、点击和转化数据。

交付物：

- 竞品分析表
- 内容营销策略
- 6 条短视频脚本
- 营销测试复盘报告

注意：预算、KPI 和实际投放结果必须由客户沟通确认，不允许虚构承诺。

输出：

- 营销方案
- 服务内容
- 项目周期
- 交付清单
- 验收标准

### 模块四：执行交付（Task Execution）

**目标：** 将营销方案转换为可追踪的执行任务，并展示交付成果。

功能：

1. 根据方案自动拆解执行任务。
2. 展示任务名称。
3. 展示任务负责人。
4. 展示任务截止时间。
5. 展示任务执行状态。
6. 展示任务完成进度。
7. 支持查看交付样例。

任务状态：

- 待开始
- 进行中
- 已完成
- 已阻塞

模拟任务：

| 任务 | 状态 |
|---|---|
| 竞品账号初筛 | 已完成 |
| 目标人群梳理 | 已完成 |
| 短视频脚本撰写 | 进行中 |
| 素材制作与审核 | 待开始 |
| 数据整理与复盘 | 待开始 |

交付样例：

短视频脚本 #01：

主题：通勤场景下的无线耳机续航体验。

包含：

- 视频开场 Hook
- 镜头设计
- 产品卖点
- CTA 行动引导

产品参数和宣传内容需要经过人工审核。

输出：

- 执行任务列表
- 任务进度
- 交付样例
- 质量审核结果

### 模块五：数据复盘（Marketing Analytics）

**目标：** 根据模拟营销数据分析效果，提出下一轮优化策略。

模拟数据：

| 内容方向 | 曝光量 | 点击量 | CTR |
|---|---:|---:|---:|
| 通勤续航 | 18000 | 720 | 4.0% |
| 音质体验 | 16000 | 400 | 2.5% |
| 外观设计 | 14000 | 320 | 2.3% |

功能：

1. 展示曝光量。
2. 展示点击量。
3. 计算点击率 CTR。
4. 对比不同内容方向。
5. 分析表现较好的内容。
6. 识别营销问题。
7. 生成下一轮优化建议。

CTR 计算公式：

CTR = 点击量 / 曝光量 × 100%

AI 复盘建议示例：

- 保留通勤续航内容方向。
- 调整音质和外观方向的内容开场。
- 为通勤人群设计不同 Hook。
- 增加落地页访问、加购和购买事件追踪。
- 联合 CTR、转化率和 CPA 进行评估。

输出：

- 营销数据指标
- 内容效果对比
- 复盘结论
- 下一轮优化建议

注意：当前缺少订单和转化数据，不得虚构 CPA 或销售增长结果。

## 5. Agent 工作流要求

产品必须体现 Agent 执行过程，而不是简单的静态页面展示。

建议采用以下执行链路：

用户输入营销目标  
→ 潜客搜索  
→ 企业信息提取  
→ 来源核验  
→ 客户匹配评分  
→ 联系内容生成  
→ 营销方案生成  
→ 执行任务拆解  
→ 交付成果生成  
→ 数据复盘  
→ 下一轮优化

每个阶段应具备：

- Run ID
- 执行状态
- 执行步骤
- 执行结果
- 错误或待人工确认信息

Run Trace 状态：

- Idle：未启动
- Running：执行中
- Success：执行成功
- Failed：执行失败

当前阶段可先通过模拟数据完成工作流演示，但需要保证状态和结果展示逻辑真实一致，不得将预置结果描述为真实模型执行结果。

## 6. UI / UX 设计要求

参考提供的 `reference/index.html`。

整体视觉方向：

- 极简、专业、现代化 SaaS 风格。
- 白色或浅灰背景。
- 深蓝色作为主要操作色。
- 低饱和度辅助色。
- 适当使用衬线字体作为大标题。
- 卡片使用轻边框和柔和阴影。
- 避免过度复杂的 Dashboard 布局。

核心布局：

顶部：

- 产品名称 Outbound Studio
- AI Marketing Copilot
- 工作空间信息
- Demo 状态标识

导航：

五个业务模块：

01 Discover  
02 Connect  
03 Propose  
04 Deliver  
05 Optimize

主体：

- 左侧：业务输入、操作和结果。
- 右侧：Agent Run Trace。
- 下方：来源核验、交付样例、数据结果等辅助内容。

交互要求：

- 顶部导航能够切换五个模块。
- 操作按钮必须具有真实可见的反馈。
- 输入内容可以编辑。
- 业务结果能够展示。
- 模块之间共享同一个模拟客户案例。
- 重要操作需要有状态提示。
- 支持桌面和移动端基本适配。

不要直接复制原型中所有静态数据和交互实现，应在理解其设计意图后进行合理重构。

## 7. 技术实现要求

优先检查现有项目的技术栈和目录结构。

开发原则：

1. 尽量复用现有项目技术栈。
2. 不要无必要地重建项目。
3. 业务模块合理拆分。
4. 数据结构尽量统一。
5. Agent 执行状态与业务数据分离。
6. 使用统一的模拟数据服务，方便后续接入真实模型。
7. 不要将 API Key 写入前端代码。

如果现有项目没有后端，可以先实现前端 Mock Service。

建议的数据结构：

- Lead：客户线索
- SourceEvidence：来源证据
- OutreachDraft：客户联系草稿
- Proposal：营销方案
- Task：执行任务
- DeliveryArtifact：交付成果
- CampaignMetric：营销数据
- AgentRun：Agent 执行记录
- AgentStep：执行步骤

未来扩展：

- Python FastAPI
- PostgreSQL
- LLM API
- 企业公开信息搜索
- CRM 集成
- 邮件服务集成
- 广告平台数据集成

以上扩展不属于当前必须实现的范围。

## 8. 验收标准

必须满足以下条件：

1. 能正常启动项目。
2. 五个业务模块均可以正常访问。
3. 可以完整演示同一个模拟客户案例。
4. 潜客分析可以展示评分和推荐理由。
5. Source Check 可以展示来源及核验状态。
6. 客户联系可以编辑和复制邮件。
7. 营销方案可以完整展示。
8. 方案可以转换为执行任务。
9. 执行交付可以展示任务状态和交付样例。
10. 数据复盘可以正确计算 CTR。
11. 能够生成下一轮优化建议。
12. Run Trace 可以展示对应的执行过程和状态。
13. 不存在虚假的真实发送、真实搜索或真实投放声明。
14. README 包含运行方式、产品思路、运营方式、技术实现和未完成项。
15. 完成基本功能验证，不存在阻塞演示的错误。

## 9. 本次开发范围限制

本项目是 1～2 小时级别的业务 Demo，不是完整商业产品。

本次不要求：

- 真实企业爬虫系统
- 大规模企业数据库
- 真实邮件发送
- 真实广告投放
- 完整 CRM 系统
- 用户权限系统
- 复杂的多 Agent 协作架构
- 生产环境部署

优先保证五个业务环节的完整性、交互性和演示效果。
