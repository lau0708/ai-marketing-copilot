# Outbound Studio｜AI 出海营销助手 Demo

面向出海营销服务商的 AI 获客与营销交付助手，可交互业务 Demo。把「潜客发现 → 来源核验 → 销售触达 → 服务方案 → 项目交付 → 数据复盘」连成一条工作流，演示一个模拟客户案例从线索到下一轮优化的完整闭环。

## 运行方式

纯前端页面可直接静态运行；如需真实 LLM 生成，再启动轻量 FastAPI 后端（可选）。

```bash
# 1) 安装后端依赖（仅首次）
pip install -r backend/requirements.txt

# 2) 可选：配置真实模型
cp backend/.env.example backend/.env
# 编辑 backend/.env 填入 DEEPSEEK_API_KEY

# 3) 启动后端（同时托管前端页面与 /api 接口）
cd backend
uvicorn main:app --reload --port 8000
# 浏览器打开 http://localhost:8000

# 纯前端方式（不接后端时自动进入模拟模式）
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000
```

项目结构：

```text
index.html              入口页面
css/styles.css          视觉样式
js/data.js              统一模拟数据服务 + 模板生成器
js/agent.js             Agent Run Trace 执行引擎
js/app.js               渲染、交互、模式检测与 LLM 联调
backend/main.py         FastAPI 入口（API + 静态前端托管）
backend/services/llm_service.py  模型调用与解析封装
backend/schemas/request.py        请求结构
backend/.env.example    环境变量示例（不含真实密钥）
docs/PRD.md             产品需求文档
reference/index.html    视觉与交互参考原型（保留未改）
```

## 演示路径

1. **潜客分析**：填写目标市场、地区、产品和行业条件；点击「运行 Agent」后，系统读取输入并在 4 条模拟线索中按行业/产品/目标市场匹配评分（未命中维度会降分）；在「Source Check」粘贴网址并点击「批量核验来源」。
2. **客户联系**：切换「设为当前案例」后，草稿引用当前企业、产品和需求信号；点击「生成邮件」按当前模式生成英文开发邮件，可编辑、复制，并查看人工审核状态。
3. **方案撰写**：编辑客户需求摘要、服务目标，并勾选服务范围；点击「生成方案」生成对应方案，复制或点击「确认方案并拆解任务」。
4. **执行交付**：任务按最新方案的服务范围自动拆解，查看任务状态、进度和交付样例。
5. **数据复盘**：可编辑曝光与点击，CTR 实时重算；点击「生成下一轮建议」前为待分析状态，运行后生成复盘结论与优化建议。

## AI 模型接入

- 采用 DeepSeek 的 OpenAI 兼容接口，统一由后端 `backend/services/llm_service.py` 调用，前端不直连模型供应商。
- 环境变量：`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`DEEPSEEK_TIMEOUT`，只从后端环境读取。
- 两种模式：顶栏「AI 模式」可切「自动 / 真实 AI / 模拟模式」。自动模式下，后端可用且已配置 Key 时走真实模型，否则走本地模拟生成。
- 生成状态区分：未生成 / 正在生成 / 已生成（真实 AI）/ 已生成（模拟）/ 生成失败。
- API Key 只保存在 `backend/.env`，不进入前端源码和浏览器请求；`.env` 已加入 `.gitignore`。

接口：

- `GET /api/health`：后端健康检查。
- `GET /api/ai/mode`：返回当前可用模式与模型名。
- `POST /api/ai/generate-email`：生成英文开发邮件。
- `POST /api/ai/generate-proposal`：生成出海营销服务方案。

## 产品思路

AI 负责信息归纳、线索初筛、邮件与方案草拟、任务拆解和复盘建议；人负责事实核验、对外审核、预算审批和交付验收。五个模块共享同一个模拟客户案例「星瀚科技（虚构）」，前一个模块的输出作为下一个模块的输入，所有操作都有对应的 Agent Run Trace（Run ID、状态、执行步骤）。

## 运营方式

从公开企业官网、行业目录、展会名录、主动咨询等合规渠道获取线索；按行业匹配、出海意向、营销能力缺口和可触达性评分排序；销售人工审核后触达。签约后把方案拆为可追踪任务，按周验收交付物，并将投放与站点数据回流到下一轮内容实验。尊重数据来源、隐私、邮件退订和平台规则。

## 技术实现

- 原生 HTML/CSS/JavaScript 单页前端；Python FastAPI + httpx 轻量后端。
- `js/data.js` 作为统一模拟数据服务与模板生成器，集中定义业务结构；真实生成时由后端返回规范化内容。
- `js/agent.js` 把 Agent 执行状态与业务数据分离；`connect`/`propose` 的 Run Trace 含真实的「请求开始 → 模型调用 → 结果返回 → 成功/失败」步骤。
- CTR 由 `点击量 / 曝光量 × 100%` 实时计算，不写死结果。
- 模型调用失败、超时、空响应均有异常处理；失败不静默回退为固定模板冒充成功。
- API Key 不进入前端代码，前端通过后端代理调用模型。

## 模拟数据声明

- 星瀚科技及所有企业线索、评分、曝光、点击、CTR 均为虚构演示数据。
- Source Check 只生成「待人工核实 · 模拟核验」清单，不访问任何网址，也不声称已核实。
- 邮件草稿只支持编辑与复制，不会真实发送。
- 营销数据缺订单与转化事件，不推断 CPA 或销售增长。
- 模拟模式下生成内容会在界面明确标注「模拟」，不伪装成真实 AI 生成。
